# bili-sync：视频与元数据分离版

这是基于 [amtoaer/bili-sync](https://github.com/amtoaer/bili-sync) 的个人分支，保留原有的收藏夹订阅、追更和管理页面，并增加适合 NAS 的分离存储方式。

## 这个分支增加了什么

- **视频单独存储**：提供本地与 CD2 两种保存方式，通过 CloudDrive2 API 将新 MP4 直接上传到网盘；直传模式会等待 CD2 上传任务完成。
- **元数据留在本地**：NFO、海报、字幕、弹幕等写入 `/media`，与视频保持相同的相对目录结构，供 Emby 读取。
- **兼容原配置**：视频源路径仍使用 `/media/...`；复用原有配置目录后，`config.toml`、数据库和订阅设置无需重建。启用分离不会自动搬迁以前下载的文件。
- **STRM 入库联动**：CD2 确认上传完成后，通过 Webhook 通知 [MediaIndex](https://github.com/xudong7587/media-index)，由其管理播放服务并生成 STRM。也可自行配置 MP 115STRM 等工具的生活事件扫描或定时增量扫描。
- **保留通用 Webhook**：MediaIndex 专用完成通知在视频网盘分流中配置，其他通知器仍可按需使用。
- **媒体库与画质管理**：点击视频源名称查看收藏时间、下载状态、保存位置及画质。手动选择视频批量对比和升级；先验证实际文件再切换，旧版本保留。页面默认只读取本地记录。
- **订阅与界面**：快捷订阅使用完整的配置表单；支持 UP 名称搜索。设置直接从侧栏进入，可切换六种主题色，设置刷新时间段和随机等待。
- **CD2 直传设置**：在「视频网盘分流」填写 CD2 地址、API 令牌和 CD2 内的网盘保存根目录。选择 CD2 模式并填写三个字段后启用；上传使用 CD2 已登录的网盘账号，无需单独扫码。原有媒体源和数据库路径仍是 `/media/...`。

## Docker Compose

仓库根目录提供带注释的通用示例 [docker-compose.yaml](./docker-compose.yaml)。部署前将其中两个 `/path/to/...` 宿主机路径替换成自己的目录，并检查端口、镜像标签和可选的用户 ID。升级已有实例时，务必将原配置目录继续映射到 `/app/.config/bili-sync`：

| 容器路径 | 用途 |
| --- | --- |
| `/app/.config/bili-sync` | 原有配置和数据库 |
| `/media` | 本地模式保存视频与元数据；CD2 模式保存元数据 |
| 原配置中的 UP 主头像路径 | 如原实例单独映射过，请沿用原映射 |

```bash
docker compose -f docker-compose.yaml up -d
```

现有视频源和追更路径不需要改为 `/video`。首次切换前请备份配置与元数据；已有视频对应的 NFO、图片等需要自行复制到新的本地 `/media` 目录。详细说明见 [视频与元数据分离](./docs/split-storage.md)。

上游使用说明和其他功能请参阅 [bili-sync 文档](https://bili-sync.amto.cc/)。本分支沿用上游 [License](./License)。

## CD2 网盘支持范围

CD2 官方列出 115、123 云盘、阿里云盘、天翼云盘、百度网盘、OneDrive 等，详见 [官方支持列表](https://www.clouddrive2.com/features.html)。夸克暂未列在该列表中，不能视为已支持。请以安装版本及账号权限为准。

本分支使用 CD2 的统一文件接口；目标需支持上传，并返回云端文件 ID、大小和 SHA1 供完成校验。115 已实测，其他网盘尚未逐一验证；连接测试只检查目录访问和容量。STRM 生成及播放还需对应工具支持该网盘。
