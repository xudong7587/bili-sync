# 媒体库工作台

## 兼容与启用

继续复用原配置数据库和 `/media` 元数据路径，原视频源、筛选规则与下载状态保持不变。新配置字段都有默认值。无需批量重置已有视频。

在「视频网盘分流」选择保存方式：本地模式将视频和元数据一起保存到原订阅目录，不使用 CD2，也不应用旧的 `/video` 分离映射；CD2 模式直传网盘。切换只影响后续保存，不迁移旧文件。界面仅提供本地 / CD2；打开旧配置时按已保存的 CD2 地址自动选择，保存后应用所选模式。后端仍可读取历史路径配置以免升级时丢失旧文件位置。已有网盘文件的播放仍可使用保留的 CD2 连接信息。

CD2 模式需保存 CD2 地址、API 令牌及保存根目录。CD2 仅通过地址和 API 令牌接入，使用已登录的网盘上传目标。

独立 115 扫码登录入口暂时隐藏。上传使用 CD2 已登录的网盘账号；旧播放链接也继续使用该连接，不读取或导出其 Cookie，也不要求再次扫码。已有的独立 115 凭据不会影响当前播放链路。

CD2 区域显示连接状态并提供测试按钮。测试直接使用当前表单内容，不保存配置；修改后测试通过仍需点「保存配置」。前端认证状态仅显示在 B 站账号页面。

## STRM 与 MediaIndex

在视频网盘分流中启用「STRM 入库联动」，粘贴 MediaIndex 的 Webhook URL 和令牌。兼容专用 `/api/webhooks/bili-sync`、通用入站连接和携带 token 的增量扫描 URL；URL 已含 token 时可不填独立令牌。MediaIndex 连接应配置 STRM 扫描操作、网盘目录和对应的本地元数据输出路径。

仅当 CD2 确认有新文件上传完成（或画质升级实际替换成功）、对应元数据写入成功后，发送 `event: finished` 完成事件。单纯刷新、更新弹幕/封面、复用已上传文件不会产生新通知。同一视频源一批新增文件合并通知一次。通知先落盘，失败时保留，并在后续下载检查中重试；同一待通知事件重试使用相同 ID。视频上传成功不会因为通知服务暂时离线而重新下载。媒体库的「通知 MediaIndex」可以为有云端记录的已下载视频补发通知。

新视频不再生成 bili-sync 自有播放 URL。既有 `/stream/...` 链接继续兼容，需要原 bili-sync 与 CD2 服务在线；完成外部 STRM 迁移前请保留这些旧服务地址。旧的 `strm_base_url` 字段保留兼容，但不控制新视频的生成流程。

没有 MediaIndex 时，可配置其他 STRM 工具，例如 MP 的 115STRM 插件，使用 115 生活事件扫描或定时增量扫描。播放链接及服务由这些工具管理，bili-sync 不自动安装或配置它们。

## 存量视频迁移

在「视频网盘分流」保存 CD2 与入库 Webhook 配置后，从左侧「存储 → 存量视频迁移」进入独立页面，预览并上传本地已下载的视频。旧版用户继续使用原配置数据库和 `/media` 映射即可；独立视频目录则填写容器内的本地视频根目录，目录结构须与 `/media` 相对路径一致。预览展示文件数、大小和前三个路径映射，不发送视频数据。

迁移清单只读取数据库中已下载成功的分 P，不递归扫描网盘，也不请求 B 站；只上传视频扩展名对应的文件，不上传 NFO、海报、字幕或 STRM。本地视频保留。已登记为网盘的视频跳过，同名远端文件须通过 CD2 内容校验后才复用；不同内容或无法确认时停止，避免覆盖。

默认每个文件之间随机等待 15–30 秒，每 10 个文件额外休息 120 秒。最短间隔不能低于 5 秒，逐个上传并等待网盘完成确认后才处理下一个。频率限制不能保证消除网盘风控，错误发生后暂停任务，由用户处理后继续。暂停等当前文件处理结束后保存进度，重启后保持暂停。修改路径或频率时重新预览，成功迁移的文件不会再次上传。仅单个文件处理期间与下载、画质操作互斥；休息时释放媒体库锁，常规任务可继续运行。每个文件开始前再核对数据库下载状态，移除或重置的视频须重新预览。

每个成功迁移登记的云端视频保存独立上传记录；若上次在上传后退出，恢复时可以复用已确认的同一文件并补发入库通知。每批合并发送一次 `event: finished`，结束或暂停时也提交剩余通知；通知失败保留待重试事件。MediaIndex 或其他兼容接收器决定扫描与 STRM 输出位置。MP 插件须支持此事件格式，不能将任意插件 URL 视为通用接收器；也可自行配置生活事件或定时增量扫描。

进度文件 `local-video-migration.json` 和 `library/` 上传记录保存在原配置目录中，应随数据库一起备份。迁移本身不会删除本地原件，建议确认外部管理器生成 STRM 并可播放后再自行清理。

## 画质管理

进入视频源，点击收藏夹/投稿/合集名称即可查看视频。页面读取数据库及本地保存记录，不主动访问 B 站或遍历网盘。

1. 筛选并选择最多 25 个分 P。
2. 点击「对比 B 站画质」。优先读取本地记录；旧视频缺少记录时，只读取所选文件的实际视频信息，再获取当前账号可访问的 B 站视频流。
3. 选择标记为可升级的视频，点击「升级所选画质」。程序重新核对候选流，下载到临时目录，验证分辨率、时长、编码、帧率和码率，再切换到新版本。

不同编码的码率不直接比较；仅画质标签提高不能证明实际画质提高。验证不通过时保留原视频。云端升级先上传临时版本并验证文件身份，再将旧视频改为 `.backup` 备份，新视频恢复原文件名，使网盘文件继续对应原元数据目录。CD2 令牌需具有重命名权限；替换事务在本地持久化，下次下载检查或画质操作会恢复未完成的替换。恢复时遇到不相符的文件身份会停止并报错。旧文件和旧记录保留，暂不自动清理。本地升级先准备新文件及旧版本备份，再原子替换视频路径。配置目录记录提交事务；中途退出后，下次启动会恢复旧文件和对应画质记录。旧版本备份记录指向实际备份文件。升级需要本地空间容纳候选文件及提交副本；不支持硬链接的文件系统还需要旧版本备份空间。

画质任务与普通下载互斥，每个分 P 之间至少等待两秒。检测到 B 站风控后停止当前批次。逐文件比较记录保存在配置目录 `quality/`，上传记录保存在 `library/`，应随数据库一起备份。

## 调度与界面

- 快捷订阅会打开完整配置表单，保存时一起提交目录、筛选规则、画质及启用状态。
- 用户投稿支持 UID 和 UP 名称搜索；同名账号请核对 UID。
- 自动刷新窗口使用容器本地时区，支持跨午夜。起止留空或相同表示全天。
- 随机间隙仅在「间隔秒数」模式自动触发后执行，等待结束再次检查时间窗口。Cron 模式按表达式触发，不追加随机等待；已保存的随机秒数保留，切回间隔模式后继续使用。修改配置会立即取消旧的随机等待。手动刷新不受窗口及随机间隙限制。
- 外观配色保存在当前浏览器，默认哔哩粉，另支持海盐蓝、鸢尾紫、蔷薇红、琥珀橙、湖水青和石墨灰。

## 当前验证范围

已验证 NAS 上 CD2 单文件定位及 Range 请求（206，仅读取 16 字节）。前端类型检查、Lint 和构建已运行；开发分支 CI 持续校验。真实 B 站搜索、云端重命名升级与 MediaIndex/Emby 入库仍需账号联调。独立 115 登录不作为当前版本的启用步骤。升级镜像本身不会批量升级既有视频。

## 仪表盘

- CPU 与内存合并为双线图；下载速度由实际接收的媒体字节数计算，每两秒更新。传输图增加「发送至 CD2」速度；另显示 CD2 上传任务的网盘传输速度，约 5 秒采样，秒传可能没有速度记录。进入 CD2 缓存不代表网盘上传完成。
- 视频分布默认按数据库中的视频个数统计（包含旧视频，一个视频含多个分 P 时计一个），可切换大小。大小只读取本地文件和已有上传/比对记录；未知网盘大小显示暂无数据，不记作零。不访问 B 站、不遍历网盘。手动画质比对会访问 B 站，需分批执行以降低风控风险。
- 视频分布同时展示本地、网盘、两地与位置待确认数量，按逐文件确认的上传记录归类，迁移期间随完成进度刷新；合集所有分 P 确认在网盘后才计入网盘数量。本地原件虽保留，已登记云端的分 P 按网盘归档计数，不重复计算大小。
- 原视频管理嵌入仪表盘下方，保留状态、时间、有效性、来源筛选和批量操作；支持来源分栏和紧凑海报卡片/表格。表格提供当前页多选、窄幅封面、截断标题、入库时间、BV/收藏时间、UP 主和任务状态；表头支持标题、入库时间、UP 主全量排序，换页/排序后清空勾选。入库时间指首次进入 bili-sync 数据库，不代表 Emby 入库时间。
- 卡片百分比表示处理步骤完成比例，不是下载字节进度；详情页可查看具体步骤状态。
- 右上角日志按钮打开弹窗；保留最近 500 条，支持级别筛选和暂停。
